# Compositor for Windows 0.5.2 — HDR, Print Color and Editing Tools

**Stable release.** Native C++20 / Qt 6 Widgets, Windows 10/11 x64.

## New capabilities

- **HDR / EXR:** import single-part RGB(A) OpenEXR and Radiance RGBE images into a floating-point layer pipeline, retain highlights above white, composite and edit HDR layers, and export floating-point EXR. Exposure adjustments can reveal those highlights. HDR layers use the reference CPU path, not an unverified GPU conversion. SDR exports explicitly clip out-of-range values.
- **CMYK print workflow:** load a printer's ICC profile from View, enable soft proofing and gamut warnings, import 8-bit CMYK PSD/PSB layers through their embedded profile (or a manually chosen profile), and export ICC-tagged CMYK JPEG, TIFF or PDF. Editing remains RGB; this is not a CMYK-channel editor. No arbitrary printer profile is silently substituted.
- **TIFF export:** RGB TIFF preserves the document's integer precision; CMYK TIFF stores the chosen print profile.
- **Progressive Blur:** linear/radial blur transitions with draggable preview endpoints, independently adjustable start/end radii and inversion. Uses interpolated blur levels; it is not a pixel-identical Core Image implementation.
- **Blur behavior:** Gaussian Preserve Transparency keeps the original alpha while blurring color. Destructive blurs can expand beyond interior layer boundaries; canvas-edge handling avoids introducing transparent borders. The default Gaussian filter radius is 5 px.
- **Content-aware extension:** fill selections beyond the original layer bounds, retaining placement, existing pixels outside the selected area and undo.
- **Smooth Corners:** optional continuous-curvature rectangle corners, using the upstream construction and retaining editable shape metadata.
- **Per-layer precision:** convert an individual layer to 8 or 16 bits without converting the other layers; reducing to 8 bits uses deterministic dithering. Converting an HDR layer to integer pixels requires confirmation in the UI.
- **RAW development:** decoder-stage LibRaw noise reduction and highlight recovery, explicit Lensfun distortion-profile loading, and a button to import directly into Camera Raw. Camera Raw parameter changes process the original-resolution source rather than a reduced working image.
- New controls, messages and import filters are available in all eight interface languages.

## Compatibility and boundaries

Supported project files remain `.comp` v1–v14. Saves use v11 for 8-bit images, v12 for 16-bit images, v13 when EXR layers are present, and v14 when Smooth Corners is used. Untouched image assets retain their original encoded bytes. Layer clipboard payloads containing HDR use a new, explicitly versioned EXR encoding; earlier Windows versions cannot paste them. Keep backups before opening newer projects in older builds.

RAW development uses LibRaw, not Apple's RAW engine. Lens correction requires a Lensfun XML file containing a single matching lens; it uses the nearest calibrated focal length and supports poly3, poly5 and PTLens distortion models. It does not automatically consume camera-embedded lens profiles or provide a bundled lens database. RAW controls therefore are not exact macOS equivalents.

Multipart/deep EXR, 32-bit PSD and PSD export are not added. EXR/RGBE input is interpreted as linear sRGB/Rec.709; arbitrary EXR chromaticities are not converted. HDR processing uses additional memory and CPU time; nonlinear legacy operations use an upstream-style highlight-normalization bridge. Float, Qt, Direct3D and Metal results are not claimed to be universally pixel-identical. Existing performance-validated GPU policies for integer documents remain unchanged.

This release addresses editing/file-format gaps, not all macOS interaction differences. Update installation and relaunch remain manual, and the application is still unsigned. No signing certificate was supplied.

## Verification

Native Release validation: **236 passed, one optional external HEIC-alpha fixture skipped, zero failed** across ten Qt Test suites (including setup/cleanup). The upstream integration suite has 29 passes, covering HDR EXR/project/clipboard round trips, highlight-preserving rendering, exposure, blur/retouch and selections; CMYK layered/composite PSD and ICC-tagged exports; TIFF precision; progressive blur; transparency; transformed expansion and linked masks; per-layer depth/undo; RAW decoder and lens corrections; and actual UI action wiring/cancel behavior. All eight catalogs have matching 647-key sets. The independently extracted portable build is checked with the same suites before publication.

## Download

Extract `Compositor-0.5.2-win-x64.zip` into a new folder and run `Compositor.exe`. Keep all bundled files together. No Qt SDK, Python, Node.js or browser runtime is required. A matching SHA-256 checksum is provided.

## 0.5.2 — HDR、印刷色彩与编辑工具

**正式版**，原生 C++20 / Qt 6 Widgets，支持 Windows 10/11 x64。

- 新增浮点 HDR 图层、单部件 RGB(A) EXR／Radiance RGBE 导入和 EXR 导出；保留超白高光，支持曝光等编辑及合成。HDR 使用 CPU 参考路径，不通过整数格式伪装高精度；导出 SDR 会裁切超出范围的高光。

- 新增可拖动端点的线性／径向渐进模糊、起止半径和反转。使用模糊级别插值，不宣称与 Core Image 逐像素一致。
- 新增高斯模糊保持透明度，完善模糊向图层外扩散和画布边缘处理，默认高斯半径为 5 px。
- 内容识别填充可扩展原图层范围，保持原有位置、选区外像素及撤销；新增上游构造的平滑圆角。
- 可单独转换图层的 8／16 位精度，不改变其他图层；转为 8 位时使用确定性抖动。HDR 转整数会在界面明确确认。

不新增多部件／深度 EXR、32 位 PSD 或 PSD 导出。EXR／RGBE 输入按线性 sRGB／Rec.709 解释，不转换任意 EXR 色度定义。HDR 会增加内存和 CPU 开销，部分非线性旧算法通过保留高光尺度的归一化桥接运行；不宣称 Qt／Direct3D／Metal 像素完全相同。整数图像保留此前经验证的 GPU 分流策略。

本版补充编辑与文件格式能力，未包含全部 macOS 交互差异。更新安装仍需手动完成；未提供证书，程序仍未签名。
