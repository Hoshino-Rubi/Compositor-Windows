## Pre-release — GPU pipeline, batch 1

**0.4.1a1 is an experimental pre-release. Stable Latest remains 0.4.0.** Keep project backups. Future GPU batches will use 0.4.1a2, 0.4.1a3, and so on, and will also be pre-releases unless a stable release is explicitly approved.

### Changes

- Cache Direct3D 11 layer-surface textures, compositing targets and readback textures across preview frames. Unchanged layers no longer repeat CPU surface preparation or upload; identical composite requests reuse the final image without dispatch or readback.
- Upload only the changed bounding rectangle of an edited layer surface, preserving 8/16-bit samples. Blend-mode-only changes reuse the existing source textures.
- Track document/viewport identities and invalidate affected cached inputs for pixel edits, masks and clipping sources, transforms, folder opacity, visibility, layer order, undo/redo and depth changes.
- Evict least-recently-used entries to stay within an estimated retained CPU/GPU cache budget of at most 512 MiB, reduced according to the adapter memory budget and availability. Oversized requests fall back to CPU. `COMPOSITOR_GPU_CACHE_MB` (1–512) lowers the cap; `COMPOSITOR_DISABLE_GPU=1` disables GPU previews and clears their cache.
- Existing project formats, export precision, eight interface languages, and native C++20/Qt 6 implementation are unchanged. No Electron or browser runtime.

### Measured result and verification

A local hardware test used a **1024×1024, 8-bit, six-layer document**, with **12 edits to a 32×32 area**. A cold-cache run cleared cached resources before each frame; the warm run reused them. In the extracted portable package:

| Measurement | Cold cache | Reused cache |
| --- | ---: | ---: |
| Total time, 12 frames | 308.505 ms | 124.306 ms |
| Source texture uploads | 288 MiB | 48 KiB |
| Texture allocations | 108 | 0 |
| CPU-prepared layer surfaces | 72 | 12 |
| Composite readbacks | 12 | 12 |

This is one controlled workload on this machine, **not a universal speedup claim or a full comparison with version 0.4.0**. A changed viewport still requires a complete compute pass and readback.

Both the native build and the extracted portable package passed **93 tests**, with **0 failures** and **1 optional HEIC-alpha fixture test skipped**. Hardware GPU tests ran rather than being skipped; all 24 blend modes and both 8/16-bit depths retain their existing output checks. New tests cover exact cache invalidation, partial upload byte counts, texture reuse, separate documents/viewports, memory-budget eviction and CPU fallback.

- ZIP size: **26,262,098 bytes**.
- SHA-256: `43e13273a00221b968908f32c04d0a73b6f778595dfef81ade5906968a70af97`; matching `.sha256` file attached.

### What is not migrated yet

Brush/eraser/clone/healing kernels, transforms, masks, filters/Camera Raw, effects and export still run on the CPU. Modified surfaces are still prepared and compared on the CPU. Changed composites still read back to Qt Widgets; this is **not zero-copy presentation or a complete GPU editing pipeline**. Existing CMYK/32-bit PSD and floating-point HDR limitations remain. GPU previews may have small rounding differences from reference CPU output; export remains on the reference CPU path.

## 预发布 — GPU 管线第一批

**0.4.1a1 是实验性预发布，稳定版 Latest 保持 0.4.0。** 测试前请保留项目备份。后续依次使用 0.4.1a2、0.4.1a3 等名称；未获得明确许可前，一律只发布为 Pre-release。

### 更新内容

- 跨预览帧缓存 Direct3D 11 图层表面纹理、合成目标和回读纹理。未变化图层不再重复由 CPU 准备和上传；相同合成请求直接复用最终图像，不再计算或回读。
- 修改图层后仅上传实际变化区域的包围矩形，保留 8／16 位样本。只改变混合模式时复用源纹理。
- 缓存区分文档与视口；像素、蒙版、剪贴来源、变换、组不透明度、显隐、层序、撤销／重做和位深变化会使相应输入失效。
- 按最近使用顺序淘汰缓存；CPU／GPU 缓存的估算保留资源总量最多 512 MiB，并按显卡报告的预算及可用量进一步降低。超预算请求回退 CPU。`COMPOSITOR_GPU_CACHE_MB`（1–512）可下调上限；`COMPOSITOR_DISABLE_GPU=1` 禁用 GPU 预览并清理缓存。
- 项目格式、导出精度、八种界面语言及原生 C++20／Qt 6 实现不变，无 Electron／浏览器运行时。

### 实测与验证

本机硬件测试采用 **1024×1024、8 位、6 个图层**的文档，在 **32×32 区域连续修改 12 次**。冷缓存对照每帧清空资源，复用组保留缓存；解压便携包结果如下：

| 指标 | 冷缓存 | 复用缓存 |
| --- | ---: | ---: |
| 12 帧总耗时 | 308.505 ms | 124.306 ms |
| 源纹理上传量 | 288 MiB | 48 KiB |
| 新建纹理数 | 108 | 0 |
| CPU 准备图层表面数 | 72 | 12 |
| 合成回读次数 | 12 | 12 |

这是本机单个受控场景，**不代表所有操作或显卡都有相同提速，也不是与 0.4.0 的全面性能对比**。发生变化的视口仍需要完整计算与回读。

原生构建和解压便携包均为 **93 项通过、0 失败、1 项可选 HEIC 透明度样本测试跳过**。硬件 GPU 测试实际执行，未跳过；24 种混合模式及 8／16 位输出检查继续通过。新增覆盖精确缓存失效、局部上传字节数、纹理复用、文档／视口隔离、预算淘汰与 CPU 回退。
