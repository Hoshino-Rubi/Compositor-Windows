# Compositor for Windows 0.4.1a8 — Reduced GPU Transfer Overhead

**Pre-release only. Stable Latest remains 0.4.0.** Experimental GPU editing remains **off by default**.

## Improvements

- Healing keeps patch-search winners, refinement offsets and reduced statistics on the GPU instead of synchronously reading them to the CPU between stages. Modes with a valid patch search need one final Map rather than five; smoothing needs one rather than three.
- Healing uploads only the relevant coverage region and reads back only the affected rectangle, directly into the immutable result image. Untouched pixels, metadata, 8/16-bit precision and the ordered solver are preserved. Solver resources remain bound across consecutive tile passes.
- Paint, eraser, clone and blur accept native BGRA8/RGBA16 regions without allocating cropped input copies or converting native channel layouts on the CPU. Staging rows go straight into the final image, avoiding an extra patch image/copy. Optional source/selection resources are omitted when unused.
- Repeated coverage rasters share one atlas entry. Unselected, translation-only brush tips reuse exact Qt coverage only when their local subpixel phase and clipped dimensions match; other geometry retains its original preparation.
- No new setting, language string, project format or runtime dependency. Existing CPU fallback, selections and undo remain in place.

## Measured results — and limits

On the tested clone-brush wrapper, elapsed GPU-path time fell about **41% (8-bit)** and **49% (16-bit)** versus a7. Healing's image readback shrank from 491,520 to 40,704 bytes in 8-bit and 983,040 to 81,408 bytes in 16-bit: **about 92% less**. Its intermediate synchronization is removed, but total healing time did **not** reliably improve; the measurements below are slightly slower. Small 8-bit core painting was essentially unchanged.

These are alternating local a7/a8 comparisons: five process-level warm medians, each from three samples, then the median across those five runs. Shader warmup is excluded; the respective operation's preparation, transfers and final readback are included. UI presentation is not measured. CPU and GPU receive the same input; existing numerical tolerances were not widened.

| Workload | Depth | a7 GPU | a8 GPU | CPU reference (a8 run) |
|---|---:|---:|---:|---:|
| Paint core, 384×320, 7 dabs | 8-bit | 0.690 ms | 0.696 ms | 0.308 ms |
| Same paint core | 16-bit | 0.969 ms | 0.838 ms | 0.599 ms |
| Clone-brush wrapper, 600×256, 256px tip, 7 dabs | 8-bit | 3.296 ms | 1.952 ms | 1.049 ms |
| Same clone-brush wrapper | 16-bit | 4.537 ms | 2.317 ms | 1.206 ms |
| Healing, 384×320 | 8-bit | 16.485 ms | 17.648 ms | 7.065 ms |
| Same healing workload | 16-bit | 16.183 ms | 16.531 ms | 7.187 ms |

The measured editing routes remain slower than CPU, so their preference stays disabled by default. This is **not** whole-stroke GPU residency, asynchronous editing or a universal speedup. A final synchronous readback and immutable CPU result copy remain; healing still uploads the full source image for patch search. Perspective, native presentation and export behavior are unchanged by this batch.

## Validation and download

Native Release validation: **189 passes, one optional external HEIC-alpha fixture skipped, zero failures** across eight Qt Test suites (counts include initialization/cleanup). GPU suites require real D3D11 execution. Added regressions check direct BGRA/RGBA uploads with nonzero/odd-stride regions, shared-coverage invalidation, exact transfer sizes, a single final healing readback, all healing modes, edge/full masks, metadata and low-budget fallback. Portable-package parity is a publication gate.

Extract `Compositor-0.4.1a8-win-x64.zip` and run `Compositor.exe`, keeping all bundled DLLs, plugins, models and licenses together. Windows 10/11 x64; SHA-256 is provided alongside the archive.

## 0.4.1a8 — 减少 GPU 传输开销

**仅预发布；稳定版 Latest 保持 0.4.0。实验性 GPU 编辑仍默认关闭。**

### 改进

- 图像修复的候选搜索、细化偏移和归约统计量留在 GPU，不再逐阶段同步回读。有有效补丁搜索的模式从五次 Map 降至最终一次，平滑模式从三次降至一次。
- 修复只上传工作区覆盖蒙版，最终只回读实际修改矩形，直接写入不可变结果图像；保留未修改像素、元数据、8／16 位及顺序求解语义。连续求解步骤不再重复解绑／绑定相同资源。
- 画笔、橡皮、克隆和模糊直接上传原生 BGRA8／RGBA16 局部像素，省去输入裁剪副本和 CPU 通道转换；回读直接写入最终图像，省去补丁图像及再次复制。未使用的来源／选区资源不再创建。
- 同批共享覆盖图只上传一次；无选区、仅平移、局部亚像素位置和裁剪尺寸精确相同的笔尖复用 Qt 覆盖，其余几何保持原路径。
- 没有新增设置、界面字符串、项目格式或运行时依赖；CPU 回退、选区和撤销保持不变。

### 实测与边界

克隆笔刷入口的 GPU 路径耗时相比 a7 下降约 **41%（8 位）／49%（16 位）**。修复样本图像回读量由 491,520／983,040 字节降至 40,704／81,408 字节，减少约 **92%**；中间同步已删除，但总耗时未稳定改善，上表中反而略慢。小范围 8 位底层画笔耗时基本持平。

上表为新旧版本交替执行五轮，每轮取三次预热计时中位数，再取五轮中位数。排除首次 shader 编译，包含各自操作的准备、传输和最终回读，不含界面显示；使用相同输入，未放宽原有像素误差门槛。

这些编辑样本仍慢于 CPU，故实验性开关不默认启用。这**不是整笔画 GPU 常驻、异步编辑或普遍提速**：仍保留最终同步回读和不可变 CPU 结果副本，修复为搜索补丁仍需上传整张来源图。透视、原生显示与导出行为未在此批变更。

原生 Release 八套 Qt Test：**189 项通过、1 项需要外部 HEIC-alpha 样本的测试跳过、0 失败**，含初始化／清理；GPU 套件强制真实 D3D11 路径。新增测试覆盖 BGRA／RGBA、非零位置及奇数行跨度、覆盖共享及失效、传输字节数、修复一次最终回读、三种模式、边缘／全图蒙版、元数据和低预算回退。便携包一致性验证是发布前的必要检查。

完整解压 ZIP 后运行 `Compositor.exe`，保留全部 DLL、插件、模型和许可证；支持 Windows 10／11 x64，附带 SHA-256 校验文件。
